# 07 技術｜核心摘要

> 技術章目前最明確的方向是：用六邊形 Tile Editor 配置整個關卡，而不是只畫背景。

## 先記住

- 所有地圖元素依附在六邊形網格上，地圖同時承載地形、水域、環境效果、物件、角色與出生點。
- `Cell` 保存地形、水域規則、環境效果、Cell 物件、角色／出生點與區域／Checkpoint 資訊。
- `Edge` 連接相鄰 Cell，保存方向、通行、邊界物件與潮流方向／強度。
- `Actor` 是玩家、敵人、Mini Boss、Final Boss 與出生點等動態單位；它們讀取所在 Cell、鄰近 Cell 與 Edge。
- 地圖資料要同時保存第一章下沉狀態與第二章上浮變異狀態：骨架保留，物件、出生點、水域與突破路徑可改。

## 編輯與驗證流程

```text
建立地圖 → 建立六邊形 Cell → 配置地形／水域／物件
→ 配置 Edge → 放置角色、Boss、Checkpoint、出生點
→ 設定第一章 → 複製為第二章變異狀態 → 地圖驗證
```

驗證至少要檢查：座標唯一、Edge 連接正確、出生點與 Boss／Checkpoint／氧氣來源有所在 Cell、互斥組合有警告，以及兩章仍保留相同骨架。

## 分層原則

```text
Cell → Cell Overlay → Cell Object → Edge → Actor
```

武器、被動能力、氧氣、體力、生命、經驗與戰鬥冷卻屬於角色／系統／遊戲狀態，不直接做成 Tile。

## 目前未定義

- 六邊形視角、排列方向與座標表示法。
- Tile Editor 使用的引擎／工具框架與地圖檔案格式。
- Cell 物件與 Edge 物件的正式互斥規則。
- 存檔、讀檔、遊戲狀態、物理需求與技術風險的具體規格。
